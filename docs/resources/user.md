# mysql_user (Resource)

The `mysql_user` resource creates and manages a user on a MySQL
server.

~> **Note:** The password for the user is provided in plain text, and is
obscured by an unsalted hash in the state
([read more about sensitive data in state](https://developer.hashicorp.com/terraform/language/state/sensitive-data)).
Care is required when using this resource, to avoid disclosing the password.

## Example Usage

```terraform
resource "mysql_user" "jdoe" {
  user               = "jdoe"
  host               = "example.com"
  plaintext_password = "password"
}

# With an authentication plugin
resource "mysql_user" "nologin" {
  user        = "nologin"
  host        = "example.com"
  auth_plugin = "mysql_no_login"
}
```

## Schema

### Required

- `user` (String) The name of the user.

### Optional

- `auth_plugin` (String) Use an authentication plugin (https://dev.mysql.com/doc/refman/5.7/en/authentication-plugins.html) to authenticate the user instead of using password authentication. Supported values are `AWSAuthenticationPlugin` (IAM authentication with Amazon Aurora) and `mysql_no_login` (the MySQL No-Login Authentication Plugin, which must be active in MySQL). Conflicts with `password` and `plaintext_password`.
- `host` (String) The source host of the user. Defaults to "localhost".
- `password` (String, Sensitive, Deprecated) Deprecated alias of `plaintext_password`, whose value is *stored as plaintext in state*. Prefer to use `plaintext_password` instead, which stores the password as an unsalted hash. Conflicts with `auth_plugin`.
- `plaintext_password` (String, Sensitive) The password for the user. This must be provided in plain text, so the data source for it must be secured. An _unsalted_ hash of the provided password is stored in state. Conflicts with `auth_plugin`.
- `tls_option` (String) An TLS-Option for the `CREATE USER` or `ALTER USER` statement. The value is suffixed to `REQUIRE`. A value of 'SSL' will generate a `CREATE USER ... REQUIRE SSL` statement. See the MySQL `CREATE USER` documentation (https://dev.mysql.com/doc/refman/5.7/en/create-user.html) for more. Ignored if MySQL version is under 5.7.0. Allowed forms: `NONE`, `SSL`, `X509`, or one or more of `CIPHER '...'`, `ISSUER '...'`, `SUBJECT '...'` joined by `AND`.

### Read-Only

- `id` (String) The ID of this resource.

## Authentication plugins

The `auth_plugin` value supports:

* `AWSAuthenticationPlugin` - Allows the use of IAM authentication with [Amazon
  Aurora](https://aws.amazon.com/rds/aurora/). For more details on how to use IAM auth with
  Aurora, see [here](https://docs.aws.amazon.com/AmazonRDS/latest/UserGuide/UsingWithRDS.IAMDBAuth.html#UsingWithRDS.IAMDBAuth.Creating).
* `mysql_no_login` - Uses the MySQL No-Login Authentication Plugin. The
  No-Login Authentication Plugin must be active in MySQL. For more information,
  see [here](https://dev.mysql.com/doc/refman/5.7/en/no-login-pluggable-authentication.html).

See also the MySQL [authentication plugins](https://dev.mysql.com/doc/refman/5.7/en/authentication-plugins.html) documentation.

## Import

Import is supported using the following syntax:

```shell
# Users can be imported using user and host.
terraform import mysql_user.jdoe jdoe@example.com
```

The import reads `tls_option` from `mysql.user` (`ssl_type`, `ssl_cipher`, `x509_issuer`, `x509_subject`): no requirement becomes `NONE`, `ANY` becomes `SSL`, `X509` stays `X509`, and specified requirements become `CIPHER '...' AND ISSUER '...' AND SUBJECT '...'` (only the parts that are set). If a value cannot be represented (for example it contains a quote), `tls_option` is left unset and a warning is logged. `tls_option` is refreshed on every read, and values that only differ in case, spacing or clause order (`ssl` vs `SSL`) do not produce a diff.

`auth_plugin` is imported only when the account uses `AWSAuthenticationPlugin` or `mysql_no_login`; for any other plugin it is left unset.

~> **Caution:** User's password can't be imported.
