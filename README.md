# terraform-mysql-provider (unofficial)
==================

Forked from https://github.com/hashicorp/terraform-provider-mysql

Documentation
-------------
Full documentation for the provider and every resource is in [`docs/`](docs/) and on the
[Terraform Registry page](https://registry.terraform.io/providers/TakatoHano/mysql/latest/docs).

Usage
-----
This Provider Support Port Forward with [AWS SSM Session Manager](https://docs.aws.amazon.com/systems-manager/latest/userguide/session-manager.html)


```hcl
terraform {
  required_providers {
    mysql = {
      source = "TakatoHano/mysql"
    }
  }
}

provider "mysql" {
  # Configuration options
  endpoint = "localhost:${unused_port}"
  username = "${aws_db_instance.db.username}"
  password = "${aws_db_instance.db.password}"
  
  aws_ssm_session_manager_client_config {
    # No SSH keys or sshd needed (AWS-StartPortForwardingSessionToRemoteHost).
    mode            = "port_forwarding"
    ec2_instance_id = resource.aws_instance.bastion.id
    rds_endpoint    = resource.aws_db_instance.db.endpoint
  }
}
```

The default `mode = "ssh"` (SSH over SSM, needs `ssh_user`/`ssh_key_path`) is
kept for compatibility; a future major version may change the default to
`port_forwarding`. See the provider docs for the required IAM permissions.

Or, Port Forwarding through public server

```hcl
terraform {
  required_providers {
    mysql = {
      source = "TakatoHano/mysql"
    }
  }
}

provider "mysql" {
  # Configuration options
  endpoint = "localhost:${unused_port}"
  username = "${aws_db_instance.db.username}"
  password = "${aws_db_instance.db.password}"
  
  port_forward_client_config {
    remote_host = resource.aws_instance.bastion.public_ip
    db_endpoint = resource.aws_db_instance.db.endpoint
  }
}
```

## Debugging

Run the provider binary with `-debug` to start it in debugger-friendly mode; it prints the `TF_REATTACH_PROVIDERS` value to use with Terraform.

## Docs

The files under `docs/` are generated by [tfplugindocs](https://github.com/hashicorp/terraform-plugin-docs) from the provider schema (`Description` fields in `mysql/`), the templates in `templates/` and the HCL/shell examples in `examples/`. Do not edit `docs/` by hand; run `go generate ./...` (or `make docs`) to regenerate it. CI fails when the committed `docs/` is stale.
